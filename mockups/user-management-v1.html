数据口径：零表结构变更

「最近登录」「今日登录」「7 天活跃」「登录失败」全部从审计日志（audit_logs 的 login / login_failed 记录，按 username 关联）推导，users 表不加字段。统计口径与审计日志页完全一致，两处数据可互相印证。

① SQL 分页 + 最近登录列（P0 后端）

list_users 目前全量查出再 Python 切片，改为 count + offset/limit 的 SQL 级分页（与审计页同一修复模式）。列表序列化附 last_login_at：audit_logs 按 username 聚合 max(created_at)，子查询一次取出，避免 N+1。

② 统计卡 + 状态筛选（P1 后端）

新增 /users/stats 聚合接口（总数 / 今日登录 / 7 天活跃 / 未分配角色数）。列表接口加 activity 参数（active_7d / dormant / never）；「未分配角色」卡片可点击，直达筛选结果。

③ 重置密码独立 + 角色卡片（P0）

编辑弹窗移除密码字段，操作列新增「重置密码」独立小弹窗（新接口 PUT /users/{id}/password，仅 admins 可用，写审计日志）。角色 checkbox 改为带描述的卡片多选，角色差异一眼可辨。

④ 用户详情抽屉 + 远期规划

点击行打开抽屉：近 30 天登录次数、最近登录、7 天失败次数 + 该用户最近动态（audit mini 时间线）。远期 P1：账号禁用需 users 加 is_active 字段并接入登录守卫，涉及迁移，本期不动表。
