# Obsidian 运维知识图谱设计

## 概述

使用 Obsidian 构建一套运维管理平台的知识图谱笔记体系，覆盖基础设施资产、告警与故障经验、运维 SOP、架构决策四大领域。采用纯手工维护方式，通过 YAML 属性 + MOC（Map of Content）+ 双向链接实现结构化知识管理。

## 目标

- 以图谱形式可视化运维知识的关联关系
- 沉淀告警处理和故障排查经验
- 标准化运维操作流程（SOP）
- 记录架构决策的背景和结论
- 支持从任意节点导航到关联知识

## 目录结构

```
运维知识库/
├── 基础设施/           # 主机、容器、集群的个体笔记
├── 告警与故障/         # 告警处理经验、故障复盘
├── 运维手册/           # SOP、部署流程、操作指南
├── 架构决策/           # ADR（架构决策记录）
├── MOC/                # Map of Content 入口索引
└── 模板/               # 各类笔记模板
```

## 笔记类型与属性

### 1. 主机笔记（Host）

文件命名：`基础设施/{主机名}.md`

```yaml
---
type: host
ip: 192.168.1.100
os: Ubuntu 22.04
status: active          # active / maintenance / retired
owner: 张三
cluster: [[生产集群A]]
tags: [生产环境, Web服务器]
---
```

正文建议包含：
- 硬件配置（CPU/内存/磁盘）
- 部署的服务列表
- 网络配置
- 维护记录

### 2. 集群/容器笔记（Cluster）

文件命名：`基础设施/{集群名}.md`

```yaml
---
type: cluster
provider: k8s           # k8s / docker
status: active
node_count: 5
tags: [生产环境]
---
```

正文建议包含：
- 节点列表及角色
- 网络配置（CNI、Service CIDR）
- 存储配置
- 关键部署物

### 3. 告警经验笔记（Alert Experience）

文件命名：`告警与故障/{告警名}-{日期}.md`

```yaml
---
type: alert-experience
alert_name: CPU高负载
severity: warning       # critical / warning / info
first_seen: 2026-01-15
resolved: true
related_hosts:
  - [[Web服务器-01]]
tags: [CPU, 性能]
---
```

正文建议包含：
- 现象描述
- 排查过程（时间线）
- 根因分析
- 解决方案
- 预防措施

### 4. SOP 笔记

文件命名：`运维手册/{SOP名称}.md`

```yaml
---
type: sop
category: 部署          # 部署 / 巡检 / 故障处理 / 备份恢复
frequency: 每周
last_updated: 2026-05-28
tags: [部署, CI/CD]
---
```

正文建议包含：
- 前置条件
- 操作步骤（编号列表）
- 回滚方案
- 注意事项

### 5. ADR 笔记（架构决策记录）

文件命名：`架构决策/ADR-{编号}-{标题}.md`

```yaml
---
type: adr
status: accepted        # proposed / accepted / deprecated / superseded
date: 2026-05-28
decision_makers: [张三, 李四]
tags: [数据库, 架构]
---
```

正文建议包含：
- 背景与问题
- 考虑的方案
- 决策结论
- 后果分析

## MOC 入口文件

`MOC/` 文件夹下有 4 个枢纽文件：

| MOC 文件 | 作用 |
|----------|------|
| `MOC/基础设施总览.md` | 按集群/机房分组列出所有主机和集群 |
| `MOC/告警经验库.md` | 按告警类型/严重级别索引所有处理经验 |
| `MOC/运维手册总览.md` | 按场景分类列出所有 SOP |
| `MOC/架构决策记录.md` | 按时间线列出所有 ADR |

MOC 文件示例：

```markdown
# 基础设施总览

## 生产集群A
- [[Web服务器-01]]
- [[Web服务器-02]]
- [[数据库主节点]]

## 测试环境
- [[测试服务器-01]]
```

## 图谱连接规则

使用 `[[双向链接]]` 建立关系：

```
主机 ──belongs_to──> 集群
主机 ──triggered──> 告警经验
告警经验 ──resolved_by──> SOP
SOP ──covers──> 主机 / 集群
ADR ──affects──> 主机 / 集群 / SOP
```

在 Obsidian Graph View 中，这些链接自动形成可视化网络。MOC 文件作为枢纽节点聚合成星形结构。

## 模板文件

`模板/` 文件夹下需要创建 5 个模板：

| 模板文件 | 对应笔记类型 |
|----------|-------------|
| `模板/主机模板.md` | 主机笔记 |
| `模板/集群模板.md` | 集群/容器笔记 |
| `模板/告警经验模板.md` | 告警经验笔记 |
| `模板/SOP模板.md` | SOP 笔记 |
| `模板/ADR模板.md` | ADR 笔记 |

## 使用流程

1. **新建主机** → 用模板创建笔记 → 填写属性 → 在基础设施 MOC 中添加链接
2. **处理告警** → 创建告警经验笔记 → 关联受影响主机 → 写处理过程
3. **沉淀 SOP** → 创建运维手册笔记 → 关联覆盖的主机/集群 → 链接相关告警经验
4. **架构决策** → 创建 ADR → 记录背景、方案、结论 → 关联受影响的系统

## 图谱查看

- **全局图谱** `Ctrl+G` — 查看所有笔记的链接关系，识别枢纽和孤立节点
- **局部图谱** — 打开任意笔记后点右上角图谱图标，查看当前笔记的关联网络
- **MOC 导航** — 从 MOC 文件出发，按链接跳转到具体笔记

## 维护原则

- 新增资产必须创建对应笔记并链接到 MOC
- 每次告警处理后花 5 分钟写经验笔记
- SOP 变更时同步更新笔记的 `last_updated` 属性
- 图谱中出现孤立节点时及时补充链接

## 依赖

- Obsidian（已安装）
- Templater 插件（用于模板套用）
