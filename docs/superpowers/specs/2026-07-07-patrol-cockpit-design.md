# 巡检态势大屏沉浸式改造设计

日期：2026-07-07

## 背景

当前 `PatrolCockpitView` 已经具备巡检大屏的基础骨架：健康分、严重/警告/正常统计、覆盖分布、风险拓扑、风险事件、趋势图和重点对象表格。但整体仍更像一个暗色后台仪表盘，而不是展示型态势大屏，主要问题有：

1. 中央视觉焦点不够强，风险拓扑没有形成远距离可读的“态势核心”。
2. 顶部指标、左右面板、底部表格的层级比较平均，用户第一眼不容易判断当前是否危险。
3. “科技感”主要来自暗色背景、网格和卡片，并没有由数据空间、状态光效、风险热区和战报节奏建立起来。
4. 现有页面仍保留较强后台页面气质，适合近距离操作，但不适合监控墙或会议屏展示。

本次设计目标是把巡检态势大屏改造成展示优先的沉浸式战情大屏，而不是继续增加普通数据卡片。

## 已确认方向

经过视觉方向讨论，最终采用：

1. 视觉方向：`B. 战情指挥中心`
2. 布局方向：`B2. 指标顶栏 + 底部战报`
3. 使用场景：监控墙/大屏展示为主
4. 外壳模式：沉浸展示模式

这个方向意味着页面应优先服务远距离判断和全局展示，而不是像桌面处置页一样承载完整表格操作。

## 目标

1. 值班人员或观看者在 3 秒内能判断当前巡检态势是否安全。
2. 页面第一视觉焦点明确落在中心风险雷达/态势图。
3. 顶部指标能清楚表达健康分、严重项、警告项、覆盖对象和最近巡检时间。
4. 左右面板解释“哪里出问题”，底部战报解释“刚发生了什么”。
5. 整体气质比当前版本更高级、更科技，但仍保持运维平台需要的克制、可靠和可读性。

## 非目标

1. 不新增后端接口，第一版复用现有巡检报告和巡检详情接口。
2. 不把大屏改成可深度操作的数据表格页。
3. 不引入重型图表库，优先使用 Vue、CSS、语义 SVG 完成核心视觉。
4. 不把页面做成纯装饰屏，所有视觉变化都必须对应数据状态。
5. 不移除返回指挥台和立即巡检能力，但这些操作不能抢占展示焦点。

## 页面定位

`/patrol/cockpit` 定位为“巡检态势展示屏”。它与 `/patrol` 的关系如下：

1. `/patrol` 是巡检指挥台，负责批次选择、对象处置、导出、删除和跳转。
2. `/patrol/cockpit` 是态势大屏，负责全局展示、风险判断和重点对象播报。

因此，大屏里的“重点对象明细表格”应降级或重构为战报/队列，不再作为页面底部的大面积普通表格存在。

## 总体布局

页面采用沉浸式 16:9 优先布局，并在普通后台工作区内尽量占满可用空间。

### 1. 顶部大屏标题区

顶部不再使用普通后台 page header，而是使用中轴对称的大屏标题条：

1. 中间：`巡检态势大屏` 或 `巡检战情驾驶舱`。
2. 左侧：报告标题、报告时间、操作人或系统任务。
3. 右侧：返回指挥台、立即巡检、可选全屏入口。

标题区要轻，不能占用过多垂直空间。它的作用是建立大屏身份和提供必要安全出口。

### 2. 顶部指标顶栏

标题下方放一行核心指标，建议 5 个：

1. 健康分
2. 严重项
3. 警告项
4. 覆盖对象
5. 最近巡检

视觉原则：

1. 健康分作为主指标，尺寸略大。
2. 严重、警告使用语义色，但不大面积铺满红黄。
3. 每个指标应包含数字、标签和短说明。
4. 指标在远距离应清晰，不使用过细字体或低对比灰字。

### 3. 中心风险雷达

中心区域是最大视觉焦点，替代当前“风险拓扑”的静态节点图。

中心雷达建议表达：

1. 按对象分布的风险热区。
2. P1/P2 对象点位。
3. 对象类型层级：主机、K8s、资产。
4. 当前选中或轮播对象的简短摘要。

视觉元素可以包括：

1. 圆形雷达刻度或同心风险环。
2. 细网格背景。
3. 风险点脉冲，但只用于异常点。
4. 中心健康态势文案，如 `需处置`、`需观察`、`运行平稳`。

动效应服务状态：雷达扫光、风险点轻微脉冲、对象轮播高亮。必须提供 `prefers-reduced-motion` 降级。

### 4. 左侧风险队列

左侧放优先级队列，聚焦 P1/P2 对象：

1. 默认展示最多 5 个重点对象。
2. 每项包含对象名、类型、优先级、异常摘要和异常计数。
3. P1 排在 P2 前面。
4. 无异常时展示“暂无 P1/P2 风险对象”，并强化全局健康状态。

这一区域解释“最该关注谁”，不承载完整对象明细。

### 5. 右侧分布与趋势

右侧放覆盖分布和短趋势：

1. 主机、K8s、资产三类覆盖对象数量。
2. 严重/警告/正常的比例条。
3. 最近 7 次巡检的异常趋势。

趋势图应保持简洁，不做复杂坐标轴。用于判断风险是在收敛还是扩大。

### 6. 底部战报 ticker

底部替代当前普通明细表格，使用横向战报/事件条：

1. 最近风险事件：对象名、风险结论、影响范围。
2. 最近巡检批次摘要。
3. 当前报告的异常总量和状态变化。

展示屏可自动横向轮播，但需要确保内容默认可见，不能依赖动画才能读到。若用户启用减少动态，则改为静态列表。

## 关键状态

### 加载中

使用大屏骨架屏，不在中心放单个 spinner。中心雷达、顶部指标和左右面板分别显示 skeleton。

### 暂无报告

中心展示明确空状态：

1. 标题：`暂无巡检报告`
2. 说明：`执行一次巡检后将展示健康分、风险分布和战报。`
3. 主操作：`立即巡检`

空状态仍应保持大屏结构，避免整页塌成普通提示。

### 全部正常

中心雷达进入低风险状态：

1. 健康分突出。
2. 风险点隐藏或转为低亮度健康点。
3. 左侧风险队列展示“暂无高优先级风险”。
4. 底部战报展示最近正常巡检摘要。

### 存在 P1/P2

1. P1 对象在中心雷达和左侧队列同步高亮。
2. 严重项指标使用危险色强化，但不让整屏变红。
3. 底部战报优先展示 P1 相关事件。

### 接口失败

保留大屏背景和结构，中心显示错误状态：

1. 标题：`巡检态势加载失败`
2. 说明尽量区分报告列表失败或详情失败。
3. 操作：`重试`、`返回指挥台`

## 数据与实现

第一版复用现有数据来源：

1. `getPatrolReports({ page: 1, page_size: 7 })`
2. `getPatrolReportDetail(reportId)`
3. `runPatrol()`
4. `buildPatrolOverview()`
5. `buildRiskObjects()`
6. `groupRiskObjectsByCategory()`

建议新增或扩展前端计算：

1. `priorityObjects`：P1/P2 对象，最多取 5-8 个。
2. `radarObjects`：映射到中心雷达的对象点位。
3. `tickerItems`：底部战报事件。
4. `trendSummary`：最近巡检趋势摘要。

雷达点位第一版可以使用确定性布局，不需要真实拓扑坐标：

1. 按对象类型分环或分区。
2. 按风险等级决定亮度、尺寸和排序。
3. 使用对象 index 计算稳定位置，避免每次刷新跳动过大。

## 响应式策略

大屏优先设计桌面和 16:9 显示：

1. `>= 1280px`：完整 B2 布局。
2. `900px - 1279px`：中心雷达在上，左右面板改为两列或上下堆叠。
3. `< 900px`：降级为单列摘要页，保留顶部指标、风险队列、趋势和战报。

移动端不追求大屏沉浸感，优先保证可读和不溢出。

## 视觉原则

1. 使用深色沉浸背景，但避免整屏单一蓝紫色。
2. 科技感来自层级、精密线条、数据光效和状态动效，不来自大量装饰。
3. 卡片边界要轻，减少普通后台卡片感。
4. 红黄绿只表达状态，不做无意义装饰。
5. 所有小字必须保证对比度，不使用过浅灰色。
6. 不使用大圆角卡片，保持项目现有 8px 半径倾向。

## 动效边界

允许：

1. 雷达扫光。
2. 异常点轻微脉冲。
3. 底部战报 ticker。
4. 指标值刷新时的短暂强调。
5. 面板 hover 或 active 的细微状态变化。

不允许：

1. 大面积页面入场动画。
2. 让内容依赖动画后才出现。
3. 闪烁式告警效果。
4. 与数据状态无关的装饰动效。

## 可访问性

1. 保留语义文本，不只用颜色表达风险。
2. 所有可点击元素需要 keyboard focus 和明确 aria label。
3. SVG 雷达需要 `role="img"` 和描述性 `aria-label`。
4. 动效必须支持 `prefers-reduced-motion: reduce`。
5. 颜色对比需要满足 WCAG 2.1 AA 基线。

## 建议实现顺序

### 阶段一：结构重组

1. 重构 `PatrolCockpitView.vue` 模板为沉浸式大屏布局。
2. 移除或降级当前底部大表格。
3. 建立顶部标题区、指标顶栏、中心雷达、左右面板、底部战报区域。

### 阶段二：数据映射

1. 基于现有 `riskObjects` 生成雷达对象。
2. 基于 `reports` 和 `priorityObjects` 生成 ticker。
3. 优化趋势图数据映射，展示最近 7 次巡检态势。

### 阶段三：视觉与动效

1. 完成深色沉浸背景和面板层级。
2. 加入雷达扫光、风险点状态和 ticker 动效。
3. 添加 reduced-motion 降级。
4. 校验桌面、窄屏和空状态。

## 验收标准

1. 打开态势大屏后，第一眼能识别这是展示型巡检大屏，而不是普通后台页面。
2. 3 秒内能判断当前是否存在 P1/P2 风险。
3. 中心风险雷达是页面最强视觉焦点。
4. 顶部指标能完整表达健康分、严重项、警告项、覆盖对象和最近巡检时间。
5. 左右面板能解释风险对象、对象类型分布和趋势。
6. 底部战报能替代当前普通明细表格，提供展示场景下更合适的信息节奏。
7. 页面在无报告、全部正常、存在 P1/P2、加载失败时都有明确状态。
8. 视觉上更高级、更科技，但没有牺牲文本可读性和状态可理解性。

## 推荐实现参考

实现阶段建议重点参考 impeccable 的以下方向：

1. `layout.md`：用于复杂大屏布局和空间层级。
2. `animate.md`：用于雷达、ticker 和状态反馈动效。
3. `colorize.md`：用于避免暗色页面变成单一蓝紫主题。
4. `audit.md`：用于完成后的可访问性、响应式和性能检查。
