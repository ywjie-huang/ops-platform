# 模型选择下拉框优化设计

## 背景

模型配置页在刷新模型列表后使用原生 `datalist` 展示候选项。浏览器负责渲染该浮层，项目无法可靠控制宽度、最大高度、滚动、空状态和候选项信息层级。模型较多时，浮层会变成狭窄且接近整页高的长列表，遮挡主要配置内容。

## 目标

- 保留手动输入任意模型名称的能力。
- 支持搜索并选择刷新得到的模型。
- 下拉层与输入控件对齐，限制高度并在内部滚动。
- 使用项目已有的 Element Plus 控件语义，覆盖键盘、焦点、加载、空结果和校验状态。
- 在桌面端和移动端均不挤压或遮挡相邻内容。

## 非目标

- 不修改模型发现接口及其返回结构。
- 不对模型按能力或类型分组，因为当前接口没有可靠的分类元数据。
- 不增加模型收藏、最近使用或分页能力。
- 不改变配置保存、连接测试或 Profile 管理流程。

## 方案

将 `ConnectionForm.vue` 中的原生 `input + datalist` 替换为 Element Plus `el-select`，启用 `filterable`、`allow-create` 和 `default-first-option`。`profile.model` 仍是唯一表单值，用户既可选择已有候选项，也可输入任意模型 ID 后采用。

候选项以模型 ID 为主信息；存在 `owned_by` 时，将其作为弱化的辅助信息显示。长文本保持单行并省略，完整内容通过原生 `title` 提示。下拉层最大高度约 280px，超过约 7 项后内部滚动，并保持与选择控件对齐。

刷新按钮继续位于控件右侧。刷新期间按钮进入加载和禁用状态，但已填写的模型值保持不变。无候选项时显示“暂无可选模型，可直接输入模型名称”；输入筛选无匹配时仍允许创建当前值。

## 交互与校验

- 选择或创建模型后立即触发模型字段校验，清除已有的空值错误。
- 失焦时继续执行现有校验。
- 候选项支持方向键移动、Enter 选择、Esc 关闭，焦点样式沿用设计令牌。
- 控件提供明确的 `aria-label`，刷新按钮保留可识别的加载文案。
- 900px 以下表单仍改为单列；窄屏下模型输入与刷新按钮改为上下布局，按钮保持可点击宽度。
- 动效仅用于下拉层状态变化，并遵守 `prefers-reduced-motion`。

## 实现边界

主要改动限定在：

- `frontend/src/views/ai/model-config/components/ConnectionForm.vue`
- 针对模型选择行为新增或补充前端测试

不改变 `ModelConfigView.vue` 的模型拉取数据流和后端接口。

## 测试与验收

- 刷新返回大量模型时，下拉层高度受限且内部可滚动，不再形成整页长列表。
- 输入关键字可以过滤候选项。
- 输入列表外的模型名称可以保留并提交。
- 选择候选项或创建自定义值后，空值错误立即清除。
- 加载、空列表、长模型 ID、带或不带 `owned_by` 的候选项均可正常显示。
- 键盘可以打开、导航、选择和关闭下拉层。
- 桌面端与移动端布局无溢出和遮挡。
- 前端测试和生产构建通过，并在浏览器中完成截图检查。

## 风险与缓解

- Element Plus 下拉层通过 teleport 渲染，scoped CSS 无法直接覆盖内部节点。使用稳定的 `popper-class` 作为受控样式入口，避免全局污染。
- `allow-create` 的创建提示能力受组件版本限制。优先保证可输入和可提交；提示文案通过字段帮助文本和空状态表达。
- 模型列表可能非常大。当前接口数据量适合客户端过滤；若未来达到数千项，再单独评估服务端搜索或虚拟列表。
