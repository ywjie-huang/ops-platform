# 空数据初始化与演示数据清理设计

## 背景

全新部署会由 `backend/app/db/init_db.py` 自动创建三台演示资产和三条演示工单。主机监控复用资产表，因此同样展示这些虚拟主机。Prometheus 与 Alertmanager 还使用项目环境的硬编码地址作为默认值，导致未配置的新部署读取到外部告警规则。

## 目标

- 新数据库只初始化系统运行必需的数据，不初始化资产、工单或监控规则等业务数据。
- 未配置 Prometheus 或 Alertmanager 时，健康检查返回未连接，列表接口返回空数据，且不发起 HTTP 请求。
- 升级已有部署时，自动清理由旧版本创建且仍保持原始内容的演示资产和演示工单。
- 不删除用户创建或修改过的真实数据。

## 实现

1. 从 `init_db()` 移除 `_seed_assets()` 和 `_seed_tickets()` 调用，并删除对应种子函数。
2. 增加一次性、幂等的演示数据清理函数。工单按标题、描述、优先级、状态和负责人完整匹配；资产按名称、IP、类型、状态、负责人、规格、系统和描述完整匹配。仅完整匹配时删除。
3. 先清理精确匹配的演示工单，再清理精确匹配的演示资产，避免外键关系影响清理。
4. 将 `config.py` 与 `settings.py` 中 Prometheus、Alertmanager 默认地址改为空字符串，并允许通过现有环境变量显式配置。
5. 在 Prometheus 和 Alertmanager 服务入口对空地址短路，返回空结果或未连接状态。

## 数据安全

- 清理条件使用全部稳定业务字段，不仅依赖名称或 IP。
- 任一字段被用户修改后，该记录不再符合清理条件并被保留。
- 清理函数可重复运行；目标记录不存在时不产生副作用。
- 管理员、权限、系统角色和默认发布环境继续正常初始化。

## 测试

- 验证 `init_db()` 不再调用资产和工单种子函数。
- 验证精确匹配的演示数据会被清理。
- 验证修改过的同名资产或工单不会被清理。
- 验证空监控地址不会创建 HTTP 客户端，并返回空数据或未连接状态。
- 运行后端完整测试集。
